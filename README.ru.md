Instagram Direct → Telegram уведомления


Отслеживает Direct-сообщения от конкретных людей в Instagram и шлёт
уведомление в Telegram — но только если ты сам(а) ещё не видел(а) это
сообщение (например, не был(а) только что в этом чате).


🇬🇧 English version: README.md




⚠️ Дисклеймер: проект использует instagrapi —
неофициальную библиотеку, которая эмулирует мобильное приложение
Instagram. Официального API для мониторинга личных Direct-сообщений не
существует. Использование этого метода нарушает условия использования
Instagram и несёт реальный риск временной блокировки или запроса
challenge. Используй на свой страх и риск, на аккаунте, потерю
которого ты готов(а) пережить. См. раздел Риски ниже.





Возможности


Отслеживает один или сразу несколько Instagram-аккаунтов (по нику).
Шлёт сообщение в Telegram только тебе (один admin chat ID), когда
контакт тебе пишет — с его ником и типом контента (текст,
фото, видео, reels, голосовое, репост story и т.д.).
Не шлёт уведомление, если ты уже сам(а) прочитал(а) сообщение
(например, был(а) в этот момент в чате) — никакого дублирования
уведомлений о том, что ты уже видел(а).
Сохраняет сессию и "отпечаток устройства", чтобы не выглядеть как
новый "телефон" при каждом запуске (это сильно снижает риск бана).
Опциональная поддержка двухфакторной аутентификации (TOTP) — 2FA
отключать не нужно.
Опциональная поддержка прокси.
Переживает перезапуски — помнит последнее обработанное сообщение по
каждому контакту отдельно.


Как это устроено (архитектура)


┌─────────────────┐   опрос раз в ~40-80 сек          ┌──────────────────┐
│  Instagram        │ <──────────────────────────────  │  instagram_dm_   │
│  (через instagrapi)│ ───────────────────────────────> │  monitor.py      │
└─────────────────┘   треды Direct + статус прочтения   └─────────┬────────┘
                                                                    │
                                          новое непрочитанное       │
                                          сообщение                 ▼
                                                          ┌──────────────────┐
                                                          │  Telegram Bot API │
                                                          │  (твой admin ID)  │
                                                          └──────────────────┘



Скрипт — это один долгоживущий Python-процесс с одним главным циклом
(main() в instagram_dm_monitor.py):


Логин (ig_login()) — заходит в Instagram один раз, сохраняет
сессию и "отпечаток устройства" в ig_session.json, и переиспользует
их при каждом следующем запуске/повторной попытке, чтобы Instagram не
видел "новое устройство" каждый раз.
Резолв контактов (build_targets()) — для каждого ника из
TARGET_USERNAMES находит его user_id, открывает/создаёт тред
Direct с ним и запоминает thread_id.
Цикл опроса — каждые ~40-80 секунд (случайный интервал, чтобы не
выглядеть как робот с фиксированным таймингом):

Забирает тред по каждому отслеживаемому контакту.
Сравнивает последние сообщения с последним обработанным
(хранится в ig_monitor_state.json, отдельно по каждому контакту).
Для каждого нового сообщения от контакта (не от тебя самого):

Проверяет thread.last_seen_at — видел(а) ли ты уже
сообщение с таким же или более поздним id (is_already_seen_by_me()).
Если да — то есть ты уже был(а) в чате — уведомление пропускается.
Иначе шлёт сообщение в Telegram: ник + тип контента
(send_telegram_message(), подписи типов — в словаре
CONTENT_TYPE_LABELS).




Засыпает, повторяет. При истечении сессии перелогинивается сам.

Способы входа


Скрипт поддерживает переключаемые способы входа через IG_LOGIN_METHOD.
Смотри ig_login() в коде — он написан так, что добавление нового
способа — это просто новая ветка if IG_LOGIN_METHOD == "...", которая
возвращает залогиненный instagrapi.Client.


password (по умолчанию)


Обычный вход по логину и паролю. Сессия и отпечаток устройства
кешируются в ig_session.json после первого успешного входа и
переиспользуются дальше — это важно: Instagram считает подозрительным,
если при каждой попытке входа "устройство" новое.


Поддерживает TOTP-2FA (IG_TOTP_SECRET) автоматически — код вводить
руками не нужно, отключать 2FA тоже не нужно.


session


Полностью пропускает вход по паролю и ожидает, что готовый файл
ig_session.json (settings/сессия от instagrapi) уже существует —
например, экспортирован из другого скрипта, с другой машины, или
получен один раз интерактивно. Если файла нет — скрипт сразу
останавливается с понятной ошибкой, а не тихо откатывается на вход по
паролю.


export IG_LOGIN_METHOD=session
# убедись, что ig_session.json лежит в рабочей директории
python3 instagram_dm_monitor.py



Как добавить свой способ входа


Открой instagram_dm_monitor.py, найди ig_login(), добавь новую ветку:


if IG_LOGIN_METHOD == "my_method":
    cl = Client()
    # ... своя логика входа ...
    return cl



Больше ничего менять не нужно — цикл опроса, уведомления в Telegram и
логика "прочитано/не прочитано" не зависят от способа входа.


Риски и ограничения


Неофициальный API. instagrapi реверс-инжинирит приватный API
мобильного приложения Instagram. Может сломаться при любом изменении
на стороне Instagram, а само использование нарушает условия
использования Instagram.
Риск бана/challenge. Особенно если: опрашивать слишком часто,
запускать несколько копий одновременно, логиниться с
"подозрительного" datacenter-IP, или генерировать новый отпечаток
устройства при каждой попытке (этот скрипт избегает последнего за
счёт кеширования ig_session.json).
Нет официального API статуса прочтения. Проверка "уже видел(а)
сам(а)" опирается на внутреннее поле Instagram last_seen_at, которое
не является документированным публичным API и может измениться без
предупреждения.
Учётные данные чувствительны. ig_session.json эквивалентен
залогиненной сессии — храни как пароль. Никогда не коммить его в git,
не делись логами, где есть он, пароль от Instagram или токен
Telegram-бота.
Проект предоставляется для личного/образовательного использования.
Ответственность за использование и соблюдение условий Instagram и
Telegram — на тебе.
